It is the mismatch between lesson-target IDs and active curriculum IDs: only 18 of 2,023 active nodes matched at least one manifest lesson asset in this snapshot. The application contract explicitly avoids guessing paths from spelling; content is not reachable merely because a file exists. This needs an explicit ID-alignment and coverage-repair programme.

## Repair and release protocol

1. Keep the broad audit fail-closed: a known blocker in the declared release corpus remains a blocker. Do not suppress a finding merely to obtain a green workflow.
2. Produce a stable repair queue from the full JSON artifact, grouped by asset, grade, subject, objective ID, field, severity, and finding code. Fix a complete high-value cluster at a time.
3. Prioritize foundational skills and prerequisite-heavy nodes first, beginning with accurate Grade 1–3 literacy/numeracy and the repaired Grade 3 mathematics cohort, while preserving the broader graph/manifest mapping work.
4. For each repaired asset, invalidate stale generation-quality scores, bind the reviewer receipt to the new exact content digest, verify all answer keys and distractors, and require an educator/accessibility/rights review as applicable.
5. Use a held-out pedagogical benchmark such as PedBench for tutor-response behavior, then run preregistered learner studies for delayed retention and transfer. A static audit is a publication-safety filter, not an efficacy test.

## Reproduction

From `mycelix-praxis/` on the audited revision:

```sh
cargo test -p praxis-curriculum-audit --lib
cargo run -p praxis-curriculum-audit -- --format=json > curriculum-quality-report.json
cargo run -p praxis-curriculum-audit -- --format=markdown > curriculum-coverage-report.md
```

The qualification workflow separately runs these reports and uploads both, even if strict blocker enforcement fails. The expected blocker failure is a measured backlog, not a reason to relax the quality gate.

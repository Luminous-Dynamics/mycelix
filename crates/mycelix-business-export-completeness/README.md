# mycelix-business-export-completeness

A small, dependency-light contract for evaluating structural completeness evidence from source-system exports.

The crate checks that a declared paginated export is internally coherent: pages are ordered, cursor hand-offs are continuous, one snapshot/query/schema/source-contract/window is used, the final page is explicitly terminal, and a provider coverage statement matches the manifest's declared scope and row count.

## What a successful assessment means

It means only that the supplied evidence is **structurally consistent** with the v0.1 contract and that a source statement claims coverage for the declared query. It does not prove the statement was actually issued by the named provider, that the provider query semantics include every economically relevant event, that the upstream system recorded every real-world event, or that a supplied metric has legal/accounting authority.

Authentication, issuer authority, independently issued control reconciliation, source-schema semantics, and real-world completeness remain separate qualification steps. The crate holds no provider credentials, performs no network access, and grants no authority or business-write capability.

The API deliberately rejects incomplete pagination chains and scope drift instead of inferring completeness from a successfully parsed file. It emits deterministic SHA-256 digests over the ordered manifest and parsed coverage projection, plus a combined evidence digest. The additive `assess_export_completeness_with_raw_payloads` entry point checks that supplied raw page bytes and the exact raw coverage-statement bytes match their declared digests, returning a distinct `RawPayloadBoundExport` result. For integrations that need a stronger dataflow boundary, `assess_export_completeness_from_raw_artifacts` passes each exact page byte slice and the exact coverage-statement bytes to caller-supplied decoders. The page decoder returns only response-owned fields—a snapshot identity, the returned cursor state, and the returned-row count—which must match those fields in the extraction receipt. Request cursor, query/scope/schema/contract identity and the local window are kept as extraction context rather than incorrectly required to be parsed from each response body. The coverage decoder receives the exact statement bytes and its decoded projection's statement digest must equal SHA-256 of those bytes before the library runs the raw-payload and structural assessment. Decode failures and projection drift fail closed. It returns a distinct `DecodedRawArtifactExport` result with a domain-separated `decoded_projection_binding_digest` over the structural projection and raw-payload evidence, so downstream records can distinguish this assessment path from `RawPayloadBoundExport`. This still trusts the decoder implementation to interpret the bytes correctly; it does not authenticate the provider, establish source-query semantics, or prove real-world completeness.

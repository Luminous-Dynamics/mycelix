## Security-specific review findings

The final manual consistency pass confirmed:

1. **Replay memory is bounded.** A connection ID enters the replay set only
   after a saturating session-budget reservation, so authenticated requests
   cannot grow the set beyond `maximum_tunnels`.
2. **CONNECT has one admitted interpretation.** The relay rejects noncanonical
   line endings, folded headers, duplicate or mismatched Host fields, request
   bodies, transfer encodings, credentials, userinfo, and malformed authority
   syntax.
3. **Evidence roots cover the logs.** Release artifacts bind the deterministic
   root and complete bytes of each build-evidence directory rather than only its
   receipt JSON.
4. **Offline signatures are fixed and rederived.** Assemblers require exactly
   64 Ed25519 bytes and 3,309 ML-DSA-65 bytes, and recompute every canonical
   payload and component message.
5. **Nix lock review is semantic.** The reviewer signs the admitted input graph,
   full revisions, NAR hashes, source tree, exact lock digest, and lock size.
6. **Reviewer identity is externally anchored.** A signature from another key
   known to the verifier agent cannot substitute for
   `PRISM_FLAKE_REVIEWER_KEY_ID`.
7. **The signed lock review is a release artifact.** Release preparation and
   verification both re-inspect the local lock and source tree; final
   verification also checks both hybrid signature components.
8. **The live gate is fail-closed.** It requires a clean tree, exact external
   artifacts, frozen Cargo commands, immutable Nix evaluation, a direct-egress
   denial in a fresh Bubblewrap network namespace, signed lock review, and
   signed release verification before publishing evidence.

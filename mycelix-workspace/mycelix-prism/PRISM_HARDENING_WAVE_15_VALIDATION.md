## Semantic review findings corrected before sealing

1. The old direct `LoadedPromotionPolicy` environment loader remained available
   after history-aware tools were introduced. It was removed so production
   promotion paths cannot bypass the rotation history.
2. Parsed promotion histories initially permitted a zero history root. The root
   is now mandatory and verified for every loaded history.
3. A transition could initially name an activation sequence at or before the
   target release-policy epoch. Activation must now be strictly later, which
   prevents a newly authorized transition from retroactively legitimizing an
   older promotion.
4. Promotion audit originally compared every historical receipt only to the
   current policy. It now selects the exact policy effective at each target
   sequence, preserving old valid checkpoints while rejecting retroactive
   substitutions.

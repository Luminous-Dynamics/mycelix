# MYC-ZKP-TIME-001R — Trusted Live-Time Contract v1

Status: **design contract / no time or authentication authority implemented**

Issue: #2192  
Parent currentness implementation: #2182

## 1. Purpose

This contract defines the first authority-bearing live-time theorem that may later strengthen `MaximumAgeSeconds` currentness evidence.

It exists because these statements are different:

```text
host wall-clock timestamp observed
!= trusted UTC current time

historical Sigstore signing timestamp
!= fresh current-time witness

fresh signed time witness
!= elapsed time through verification
```

The preferred first profile combines a freshly requested RFC3161 timestamp token with a supervisor-owned Linux `CLOCK_BOOTTIME` interval.

## 2. Authority ceiling

The strongest result from this layer is conceptually:

```text
TrustedCurrentTimeIntervalV1
```

It may establish a bounded current-time interval for one authentication attempt.

It does **not** establish:

- verifier-result correctness;
- theorem qualification;
- receipt authentication;
- production admission;
- application authority.

## 3. Existing timestamp non-equivalence

A Sigstore/Rekor/RFC3161 timestamp already attached to an artifact/signature is historical signing evidence.

It may establish that signing happened at a time accepted by the signature/certificate verification profile.

It MUST NOT be reused as the fresh current-time anchor for a later verification attempt merely because it is cryptographically valid.

```text
historical signing timestamp
!= fresh now witness
```

## 4. Preferred v1 profile

```text
exact authentication-attempt commitment
+ fresh nonce
+ RFC3161 request
+ exact TSA trust/policy profile
+ verified signed genTime / accuracy / imprint / nonce
+ bounded request roundtrip measured with CLOCK_BOOTTIME
+ bounded anchor-to-verification CLOCK_BOOTTIME interval
+ same admitted boot/time-namespace domain
    -> TrustedCurrentTimeIntervalV1
```

## 5. Attempt commitment

A time request must be specific to one authentication attempt.

Freeze a domain-separated commitment such as:

```text
MYCELIX_AUTH_TIME_ANCHOR_V1\0
|| contract_version
|| authentication_policy_commitment
|| canonical_qualification_receipt_digest
|| attestation_bundle_digest
|| retained_trusted_root_digest
|| verifier_execution_policy_commitment
|| source_revision_identity
|| signer_revision_identity
|| fresh_attempt_nonce
```

The exact serialization must be fixed-order, length-delimited and versioned before implementation.

Changing any authority-bearing field changes the commitment.

## 6. Nonce requirements

The RFC3161 request nonce is separate from the message imprint and must be unpredictable for each attempt.

Requirements:

- generated by an admitted OS CSPRNG profile;
- sufficient size for negligible replay/collision risk;
- never caller-selected through an authority-bearing public API;
- token must contain the exact same nonce when the request used one;
- reused/missing/mismatched nonce fails the fresh-anchor theorem.

The attempt commitment should also bind the fresh nonce so the message imprint and request nonce identify the same attempt.

## 7. RFC3161 token requirements

A positive anchor must establish at least:

- version/profile accepted;
- message-imprint hash algorithm accepted;
- exact message imprint equals the attempt commitment hash;
- nonce equality;
- exact TSA policy OID is admitted;
- signed `genTime` parses canonically;
- TSA accuracy is parsed and within policy;
- TSA signer certificate/chain validates under the exact admitted trust profile;
- relevant certificate/status/revocation requirements pass;
- no unrecognized critical semantics are silently ignored.

The parser/verifier library is an implementation choice, not part of this contract until independently frozen.

## 8. TSA trust identity

A URL is not the TSA trust root.

The policy must bind a versioned TSA trust profile containing the authority-significant identity required to verify the token, such as:

```text
profile_id
trusted_root_commitment
accepted_policy_oids
accepted_imprint_algorithms
maximum_accuracy
maximum_request_roundtrip
maximum_anchor_to_completion_duration
certificate/status profile
revocation/current-root profile
parser profile
```

A future Sigstore adapter may populate this from a qualified Sigstore trusted-root snapshot. Another TSA may use another separately qualified profile.

## 9. Elapsed-time clock

Use supervisor-owned Linux `CLOCK_BOOTTIME` for elapsed-time composition in the first Linux profile.

Why:

- it is non-settable;
- it is monotonic within its admitted clock domain;
- unlike `CLOCK_MONOTONIC`, it includes system suspend time;
- unlike `CLOCK_REALTIME`, it is not subject to discontinuous wall-clock changes.

This establishes elapsed duration only, not UTC by itself.

## 10. Time-namespace boundary

Linux time namespaces can virtualize `CLOCK_MONOTONIC` and `CLOCK_BOOTTIME` offsets.

Therefore:

```text
CLOCK_BOOTTIME non-settable
!= universal host clock-domain identity
```

The trusted-time profile must bind the supervisor clock domain.

A first Linux evidence profile should retain enough information to reject domain substitution, for example:

- boot-domain identifier/profile;
- supervisor time-namespace identity/profile;
- clock ID/profile;
- clock resolution;
- request, response and completion boottime readings.

The verifier child must not supply authority-bearing clock readings.

## 11. Reboot rule

Anchor and verification completion must belong to the same admitted boottime domain.

If the machine reboots between anchor acquisition and verification completion, composition fails.

A new boot requires a new trusted-time anchor.

No conversion from a pre-reboot boottime reading into the new boot domain is defined in v1.

## 12. Required readings

Record at minimum:

```text
anchor_request_boottime
anchor_response_boottime
verification_completed_boottime
```

Require:

```text
request <= response <= completion
```

and:

```text
response - request <= maximum_request_roundtrip
completion - request <= maximum_anchor_to_completion_duration
```

All arithmetic must be checked/saturating or otherwise overflow-safe and use a frozen precision/rounding profile.

## 13. Response-delay rule

A valid signed RFC3161 response received too late is not a valid fresh-time anchor for this profile.

This follows the RFC3161 timeliness concern for nonce-only clients: a network attacker can delay a legitimate response.

The allowed roundtrip is measured using the admitted suspend-aware elapsed clock, not `CLOCK_REALTIME`.

## 14. Current-time interval

Do not convert signed `genTime` directly into an exact `now` point.

The output should represent a conservative interval or conservative upper/lower bounds.

At minimum account for:

- signed TSA `genTime`;
- admitted TSA accuracy;
- bounded request timing;
- elapsed time through verification completion;
- timestamp parse precision;
- rounding policy.

For maximum-age admission, use the latest plausible completion time allowed by the evidence.

A conservative v1 upper bound may be defined from:

```text
latest_completion_time
= signed_genTime
+ admitted_accuracy
+ (verification_completed_boottime - anchor_request_boottime)
```

The exact formula must be independently audited and frozen in implementation before it gains authority.

Do not choose a more favorable point inside the interval merely to make an age threshold pass.

## 15. Attestation age composition

Only independently qualified historical attestation witnesses may supply the event/signing time being aged.

For the existing GitHub/Sigstore path, the current conservative rule is to use the oldest qualifying Public Good witness already admitted by the timestamp/root theorem.

Conceptually:

```text
conservative_attestation_age
= latest_trusted_completion_time
- oldest_qualifying_attestation_witness_time
```

A maximum-age policy passes only when the conservative age is within the threshold.

## 16. Fresh-anchor acquisition role

For a networked profile, the fresh TSA request belongs to a dedicated anchor-acquisition component.

Its strongest authority should be something like:

```text
TrustedTimeAnchorAcquisitionOnly
```

It cannot mint receipt authentication.

## 17. Offline NixOS composition

For #2319's fetcher/offline-verifier architecture:

```text
networked fetch/root/time-anchor phase
    -> retained bundle/root/RFC3161 token
    -> exact boot/time-domain handoff evidence
    -> offline verifier phase
    -> same-domain CLOCK_BOOTTIME completion sample
```

The offline verifier does not contact the TSA.

The stronger theorem fails if:

- boot domain changes;
- admitted time namespace changes;
- anchor-to-completion duration exceeds policy;
- retained token or trust profile is substituted;
- offline verifier falls back to `CLOCK_REALTIME`.

## 18. Time-namespace hardening for the NixOS adapter

A NixOS/systemd profile should either:

- ensure the supervisor samples the authoritative `CLOCK_BOOTTIME` outside verifier-created time namespaces; and/or
- explicitly prevent untrusted verifier code from creating/substituting time namespaces where that is required by the profile.

The precise systemd/kernel policy belongs to the NixOS adapter qualification, not this generic time contract.

## 19. Suggested types

Conceptually:

```rust
pub struct TrustedTimeAnchorPolicyV1 { /* private validated policy */ }
pub struct Rfc3161FreshTimeAnchorEvidenceV1 { /* serializable evidence */ }
pub struct TrustedElapsedClockProfileV1 { /* admitted clock-domain profile */ }
pub struct TrustedCurrentTimeIntervalV1 { /* opaque positive capability */ }
```

The positive capability must have private construction and no direct deserialization path from evidence JSON.

`HostObservedSystemTimeV1` must not implement an automatic conversion into the trusted-time capability.

## 20. Evidence / capability separation

Serializable evidence may contain:

- token bytes/digest;
- TSA profile ID;
- parsed genTime/accuracy;
- attempt commitment;
- nonce commitment;
- boottime readings;
- clock-domain metadata;
- accepted bounds;
- evaluation result.

That evidence must not by itself recreate the opaque trusted-time capability.

## 21. Failure taxonomy

Keep typed failures for at least:

- unsupported trusted-time profile;
- CSPRNG/nonce failure;
- message-imprint mismatch;
- nonce mismatch/missing nonce;
- unsupported imprint algorithm;
- TSA signature/chain failure;
- TSA policy mismatch;
- TSA status/revocation failure;
- token parse failure;
- TSA accuracy above policy;
- request roundtrip exceeded;
- anchor-to-completion duration exceeded;
- clock regression;
- boot-domain mismatch;
- time-namespace/profile mismatch;
- invalid interval arithmetic;
- historical timestamp substituted for fresh anchor;
- attestation age exceeds policy.

## 22. Qualification plan

### TIME-A — RFC3161 parser/verification

Prove exact imprint, nonce, policy, chain, genTime and accuracy semantics against independent fixtures/oracles.

### TIME-B — freshness / replay resistance

Prove old nonce, wrong attempt commitment, replayed token and unrelated historical Sigstore timestamp all fail as fresh anchors.

### TIME-C — elapsed clock

On the admitted Linux profile prove:

- CLOCK_BOOTTIME non-regression;
- suspend-aware elapsed accounting;
- CLOCK_REALTIME changes cannot strengthen the result;
- clock-domain/reboot mismatch rejects.

### TIME-D — network delay

Use a bounded deterministic proxy/fixture to prove a cryptographically valid response beyond the admitted monotonic roundtrip fails.

### TIME-E — age arithmetic

Exercise exact threshold boundaries, TSA accuracy, fractional precision and conservative rounding.

### TIME-F — offline composition

Acquire a fresh signed anchor in the networked phase, transfer retained evidence, disable network in the verifier phase, and prove same-domain elapsed-time composition without recontacting the TSA.

## 23. Multi-source future profile

A later higher-assurance profile may combine multiple independent TSAs or another time protocol.

That should produce a separately named interval/intersection theorem. Do not silently reinterpret one-issuer v1 evidence as a quorum.

## 24. Final theorem

```text
fresh attempt-bound signed TSA token
+ exact trusted TSA profile
+ bounded response latency
+ admitted same-domain CLOCK_BOOTTIME elapsed interval
    -> TrustedCurrentTimeIntervalV1

TrustedCurrentTimeIntervalV1
    != verifier-result correctness
    != receipt authentication
    != production admission
    != application authority
```

# Net Steward v0.2 — Trusted Federation & Operator Preview

This document outlines the design specification and implementation sequence for the **Net Steward v0.2** milestone.

## 1. Identity & Cryptographic Hardening
* **DID-Agent Binding Verification**:
  * Transition from scaffolded DID mapping to verifying signature integrity against the local Mycelix Identity DNA space.
  * Define `AgentPubKey ↔ issuer_did ↔ device_id` binding state checks.
* **Inner Signature Verification**:
  * Execute real cryptographic verification for claim envelope payloads using Ed25519 signature checks.

## 2. Reputation & Trust Dashboard
* **Trust-Weighted Telemetry Visualizations**:
  * Upgrade the dashboard peers panel to weigh incoming claims by issuer trustworthiness scores.
  * Clearly label conflicting or unsigned claims with alert states.

## 3. Session Visibility & Risk Previews
* **Read-Only Xenia Integration**:
  * Establish read-only subscription APIs tracking active operator SSH/console sessions.
* **Symtropy Blast-Radius Estimations**:
  * Model rollback plans using dry-run graph analysis to calculate structural dependencies and preview impact risks prior to operator approvals.

## 4. Remediation Gating
* **Strict Read-Only Enforcement**:
  * Ensure that while rollback plans can be mapped and visualized, no autonomous state changes or auto-remediations can bypass manual operator signature approval.

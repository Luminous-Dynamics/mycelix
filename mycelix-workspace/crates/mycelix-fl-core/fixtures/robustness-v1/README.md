# MYC-FL-001A3Q robustness fixtures v1

These fixtures are independent qualification inputs for the canonical FL aggregation line. They are not generated by `krum_v1.rs` and must not be treated as implementation-owned golden outputs.

## Frozen interpretation

For `KrumV1 { f }`:

- feasibility: `2f + 2 < n`;
- each candidate score is the sum of the `n - f - 2` smallest **squared Euclidean** distances to other admitted updates;
- distance and score arithmetic is interpreted in the canonical v1 numeric profile (`f32` coordinates, `f64` distance/score accumulation);
- lowest score wins;
- exact score ties are resolved by participant ID, then stable input index.

## Evidence classes

A fixture may establish only one of:

- `algorithm_semantics`: deterministic implementation behavior;
- `theorem_boundary`: precondition acceptance/rejection;
- `negative_scope_evidence`: a known case that should not be promoted into a broader robustness claim.

Passing these fixtures is not a universal Byzantine-robustness claim.

## Initial corpus

- `krum-v1-gross-outlier.json`: five one-dimensional updates, `f=1`; expected selector `p4` with score `0.005`.
- `krum-v1-exact-score-tie.json`: three zero-valued candidates tie at score zero; canonical participant-ID tie break selects `c` under both listed permutations.
- `krum-v1-infeasible-boundary.json`: `n=4`, `f=1`; `2f + 2 < n` is false and the profile must reject before scoring.

The numerical expectations were derived directly from the frozen equations, not from the Mycelix implementation.

## Expansion

Later corpus versions should add theorem-derived multidimensional cases, honest non-IID baselines, Byzantine attack families, selection-aware negative evidence, and context/scope matching fixtures. Those should land in separate reviewed tranches so corpus growth cannot silently change the v1 Krum theorem.

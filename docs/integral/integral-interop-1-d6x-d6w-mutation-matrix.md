# Integral Interop — D6X/D6W Mutation Matrix

Status: **ReferenceModelOnly**

This matrix defines the interoperability contract before executable golden hashes are frozen. It distinguishes semantic mutations from audit/context mutations.

| Mutation | D6S object identity | D6X semantic closure identity | D6X audit certificate | D6W input | D6W derivation |
|---|---|---|---|---|---|
| Change selected OAD production step | changes | **must change** | changes | **must change** | **must change** |
| Change selected OAD material quantity | changes | **must change** | changes | **must change** | **must change** |
| Change selected COS task production semantics | changes | **must change** | changes | **must change** | **must change** |
| Change unselected OAD certification metadata | changes full D6S object identity | **must remain unchanged** | changes only if audit projection records it | **must remain unchanged** | **must remain unchanged** |
| Add unrelated FRS observation | unchanged for selected OAD/COS objects | **must remain unchanged** | may change | **must remain unchanged** | **must remain unchanged** |
| Add unused COS candidate | unchanged for selected objects | **must remain unchanged** | may change | **must remain unchanged** | **must remain unchanged** |
| Change projection identifier only | unchanged | **must remain unchanged** | changes | **must remain unchanged** | **must remain unchanged** |
| Add runtime retrieval evidence | unchanged | **must remain unchanged** | **must change** | **must remain unchanged** | **must remain unchanged** |
| Change required D6P receipt | changes dependency set | **must change** | changes | **must change** | **must change** |
| Change derivation profile | profile identity changes | **must change** | changes | **must change** | **must change** |
| Change semantic environment | environment identity changes | **must change** | changes | **must change** | **must change** |

## Interpretation

The central rule is:

> **Semantic inputs propagate downstream; observational/audit context does not silently become semantic input.**

For Integral this means:

- OAD design semantics are dependency-bearing.
- COS task semantics are dependency-bearing when selected by the closure profile.
- Material quantities are dependency-bearing when represented as selected material nodes.
- FRS observations are not dependencies merely because they exist.
- Candidate labor or production claims are not authoritative dependencies merely because COS emitted them.
- Runtime retrieval addresses and observed commitments are evidence about resolution, not replacements for semantic identity.

## Golden-vector requirement

The next interoperability artifact should freeze the computed values for:

1. closure_identity_commitment;
2. D6X certificate commitment;
3. D6W InputCommitmentV1.commitment;
4. D6W DerivationCommitmentV1.commitment.

The vector must be generated by the Rust implementation and then independently reproduced from the canonical JSON contract. No value should be declared a cross-language golden vector until both paths agree.

## Negative requirements

A conforming implementation must **not**:

- hash the entire candidate graph as the semantic closure identity;
- include FRS observations merely because they are reachable;
- include COS candidates merely because they are emitted;
- include runtime addresses in closure_identity_commitment;
- treat a changed audit retrieval address as a changed semantic dependency;
- silently shrink a blocked closure to obtain a derivable D6W input.

Claim ceiling: **ReferenceModelOnly**.

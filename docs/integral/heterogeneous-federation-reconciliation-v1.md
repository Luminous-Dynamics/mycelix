# Heterogeneous federation branch reconciliation v1\n\nStatus: **ReferenceModelOnly**\n\nThis tranche binds heterogeneous federation to explicit branch/reconciliation semantics. A disconnected node may produce a valid local history that differs from another valid local history. Reconnection therefore does not mean "take the latest write".\n\n## Core invariants\n\n- Branch identity and frontier identity remain explicit.\n- Historical branch records are preserved after reconciliation.\n- Compatible concurrent deliveries can be union-merged deterministically.\n- The same logical delivery with different payload or origin is a conflict.\n- Reuse of the same consumed-capacity claim on both branches is never union-merged.\n- Conflicting authority dispositions or authority-validity states fail closed.\n- Stale authority is never revived by reconnect or merge.\n- Incomplete branch closure is `InsufficientEvidence`, not a mergeable state.\n- Provenance conflicts remain explicit and require an explicit-resolution path.\n- A reconciliation receipt records a new operation; it does not rewrite either input branch.\n- A cockpit projection is descriptive and cannot mint normative authority.\n\n## Compatibility\n\nThe reference classifier distinguishes:\n\n- `Equivalent` — same semantic state and no unresolved conflict;\n- `CommutativelyMergeable` — closed branches share a base and have disjoint semantic changes;\n- `MergeableWithExplicitResolution` — no hard semantic conflict, but an explicit provenance-style resolution is required;\n- `Incompatible` — authority, identity, capacity, invariant, environment, or payload conflicts prevent automatic union;\n- `InsufficientEvidence` — causal/frontier closure is incomplete.\n\nNo ordering is inferred from arrival time, timestamps, branch IDs, or reputation.\n\n## Reconciliation\n\n`MergeUnion` is permitted only for `CommutativelyMergeable` branches. It creates a third branch and retains both inputs.\n\n`PreserveConflict` records the reconciliation attempt while keeping both branches intact. This is deliberately not represented as a successful merge.\n\nThe model verifies the candidate against the current branch state before committing the reconciliation receipt. Reusing a reconciliation identity with different inputs or a different proposed resolution is rejected.\n\n## Authority and capacity\n\nAuthority is represented separately from authority validity. A stale, fenced, expired, or revoked claim may remain historical data, but it cannot be silently revived by a merged branch.\n\nConserved capacity is keyed by an explicit capacity claim. If both branches consume the same claim, the classifier produces `CapacityDoubleSpend` and automatic union is rejected. This prevents branch reconciliation from cloning consequence capacity.\n\n## Qualification boundary\n\nThe executable tests qualify only this deterministic reference behavior. They do not establish transport reliability, Holochain correctness, production federation safety, governance legitimacy, privacy compliance, or real-world outcomes.\n\nThe reference model is an oracle for runtime adapters; it is not itself a governance or authorization mechanism.
